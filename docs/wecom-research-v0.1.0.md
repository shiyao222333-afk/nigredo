# 企微群消息采集方案调研报告

> v0.1.0 步骤 1 + 步骤 2 产出 | 2026-06-26 | 从零调研，不预设方案
> 步骤 2：多平台深入调研（GitHub / 网页 / B站 / 小红书 / AI资讯），关注方案 3/4/5 + 全新方向

---

## 核心结论

步骤 1 发现 7 条技术路线，排除官方智能机器人（必须 @才触发）。步骤 2 深入调研后新增 4 条路线（共 11 条），其中 **3 条重大发现** 改变了推荐方向：

1. **影刀 RPA 社区版**（全新方向）— 免费、零代码、有专门企微群消息抓取指令 + 智能回复，**可立即验证 MVP**
2. **企业微信官方会话存档 API**（全新方向）— 官方合规方案，能拉取全部消息，但需付费 + 告知同意
3. **wecom-cli 官方 CLI 工具**（全新方向）— 2026年3月 MIT 开源、官方维护，支持消息记录拉取 + 发送文本

**推荐路线**：先影刀 RPA 社区版快速验证 MVP（零代码、当天可测），同时调研会话存档 API 的合规可行性（长期产品化方向）。

## 一、官方 API 方案

### #7 企微官方智能机器人（WebSocket 长连接）

| 维度 | 内容 |
|------|------|
| **原理** | 企微官方 API，WebSocket 长连接收发消息 |
| **SDK** | wecom-aibot-sdk（PyPI，MIT）、aibot-node-sdk（npm） |
| **收消息** | ⚠️ **仅 @机器人才触发**——不能被动监听群里所有消息 |
| **发消息** | ✅ 被动回复 + 主动推送 + 流式回复 |
| **封号风险** | ✅ 无——官方 API |
| **开发量** | 低 |
| **致命限制** | 群聊中用户必须 @机器人 才触发回调。接单群客户不会 @机器人 → **不可用** |
| **结论** | ❌ 排除 |

---

### #8 企业微信官方会话存档 API（步骤2新发现）

| 维度 | 内容 |
|------|------|
| **原理** | 企微管理后台开通后，通过 API 按 seq 增量拉取全部会话消息，RSA 解密后使用 |
| **来源** | 企业微信官方开发者文档（会话存档功能） |
| **License** | 官方 API，需企业管理员开通 + 付费 |
| **收消息** | ✅ **全部消息**（文本/图片/语音/视频/文件/名片/红包/撤回等 30+ 类型） |
| **发消息** | ❌ 会话存档 API 只读，**不能发消息**（发消息需配合其他 API） |
| **封号风险** | ✅ 无——官方 API |
| **平台** | 服务器端运行，不需要手机/电脑 |
| **合规要求** | ⚠️ 必须告知员工和客户（同意后方可存档），有 5 天数据保留限制 |
| **费用** | 需企业微信付费版（具体费用取决于企业微信版本） |
| **开发量** | 中——需要实现 seq 增量拉取 + RSA 解密 + 消息类型解析 |
| **技术细节** | 1. 获取 `seq` → 2. 调用 `get_chat_data` 拉取 → 3. RSA 私钥解密 → 4. 解析消息体 |
| **优势** | 官方合规、全消息类型、无封号风险、可产品化 |
| **劣势** | 只读不能回复（需配合智能机器人或其他方式发送）、需付费、需告知同意、5天限制 |
| **结论** | ⚠️ 收消息可走此方案，但发消息需另找路径。适合长期产品化的"收"端，不适合 MVP 快速验证 |

---

### #9 wecom-cli 官方 CLI 工具（步骤2新发现）

| 维度 | 内容 |
|------|------|
| **原理** | 企业微信官方团队开源的命令行工具，基于智能机器人 Bot ID + Secret 认证 |
| **来源** | github.com/wecom-team/wecom-cli（WecomTeam 官方维护） |
| **License** | **MIT**（2026年3月开源） |
| **最新版本** | v0.1.9（2026-05-27） |
| **收消息** | ✅ `wecom-cli msg record` — 拉取消息记录（文本/图片/文件/语音/视频） |
| **发消息** | ✅ `wecom-cli msg send-text` — 发送文本消息 |
| **其他能力** | `wecom-cli chat list` — 会话列表查询 |
| **封号风险** | ✅ 无——官方 API 封装 |
| **平台** | 跨平台 CLI（Go 编译，Windows/Linux/macOS） |
| **认证方式** | 智能机器人 Bot ID + Secret（需在企微管理后台创建智能机器人） |
| **开发量** | 低——CLI 调用，无需写底层 API 对接代码 |
| **关键疑问** | ⚠️ 基于智能机器人 API，消息记录拉取是否同样受"仅 @机器人才有记录"限制？需实测验证 |
| **优势** | 官方维护、MIT 开源、跨平台、低开发量 |
| **劣势** | 功能较少（目前仅文本发送）、认证依赖智能机器人（可能继承 @限制）、CLI 形态不适合长期运行 |
| **结论** | ⚠️ 如果消息记录拉取不受 @限制 → 可作为"收"端方案。如果受限 → 只能配合 #7 做被动回复。**需实测验证** |

## 二、协议层拦截

### #1 PC Hook（DLL 注入）

| 维度 | 内容 |
|------|------|
| **原理** | 将 DLL 注入企微 PC 进程，拦截 SendMsg/RecvMsg 函数，在本地启动 HTTP API |
| **代表项目** | WeChat-Work-Hook（github.com/xing653245/WeChat-Work-Hook） |
| **License** | 商业授权（100元/月，Star后可试用7天） |
| **收消息** | ✅ 全部消息（文本/图片/文件/语音/视频），实时回调 |
| **发消息** | ✅ 全部类型 |
| **群管理** | ✅ 拉人/踢人/改群名/群公告/获取群成员 |
| **封号风险** | 低——真实客户端在运行，指纹与真人一致 |
| **平台** | Windows 10/11 only |
| **版本锁定** | ⚠️ 锁定企微 v4.1.36.6012，不能升级 |
| **开发量** | 低——调用方只需 HTTP POST |
| **维护** | 企微更新时需要作者更新 Hook 偏移地址 |
| **最近活跃** | 2026-05-19（CSDN 文章），GitHub 有 Releases |
| **结论** | ❌ 商业依赖 + 版本锁定，不适合产品化 |

### #2 iPad 协议（逆向二进制协议）

| 维度 | 内容 |
|------|------|
| **原理** | 逆向企微 iPad 客户端的 Protobuf 通信协议，在服务器端完全模拟登录/心跳/收发消息 |
| **代表服务** | QiweAPI（qiweapi.com）、各类 SCRM 供应商 |
| **License** | 商业 SDK（需问价） |
| **收消息** | ✅ 全部消息，毫秒级推送 |
| **发消息** | ✅ 全部类型 |
| **群管理** | ✅ 完整 |
| **封号风险** | ⚠️ 较高——指纹模拟不当会被风控系统识别 |
| **平台** | 服务器端运行，不需要手机/电脑 |
| **并发** | 极高——单服务器支撑 600+ 账号 |
| **开发量** | 自研极高（精通汇编/加密/协议栈）；用商业 SDK 则低 |
| **维护** | 企微协议升级时全部瘫痪，需更新逆向结果 |
| **技术细节** | MMTLS 安全传输层 + Protobuf 序列化 + 反调试检测 |
| **结论** | ⚠️ 法律风险高，不适合产品化 |

### #4 PC 桌面自动化（OCR + 模板匹配）（步骤2深入调研）

| 维度 | 内容 |
|------|------|
| **原理** | 截图 → OpenCV 模板匹配定位按钮 → OCR 识别文字 → 模拟鼠标键盘 |
| **技术栈** | uiautomation（窗口管理）+ OpenCV（模板匹配）+ EasyOCR（文字识别）+ pywinauto（键鼠模拟） |
| **License** | 全部开源（Python 库） |
| **收消息** | ⚠️ 通过 OCR 读取屏幕文字，精度和效率有限 |
| **发消息** | ✅ 模拟手动输入 |
| **封号风险** | 低——完全模拟人工操作 |
| **平台** | Windows |
| **开发量** | 中高——需要处理 DPI、坐标转换、模板维护 |
| **关键问题** | ⚠️ 企微 4.x+ 采用 Canvas 自绘 UI，传统 UIAutomation 控件树完全失效，Inspect.exe 看不到任何控件 |
| **维护** | 企微 UI 改版时需要重新截模板图；OCR 模型可能需调优 |
| **参考** | github.com/Hello-Mr-Crab/pywechat（微信版，非企微） |

#### 步骤2深入发现

| 调研项 | 结果 |
|--------|------|
| GitHub 新开源项目 | ❌ 未找到企微 4.x Canvas UI 的 OCR 自动化开源项目 |
| pywechat 是否适配企微 | ❌ pywechat 针对微信，不是企微。企微 Canvas UI 架构与微信不同 |
| uiautomation 可行性 | ❌ 企微 4.x 全 Canvas 自绘，UIAutomation 控件树完全失效，无法用控件定位 |
| 纯 OCR 路线可行性 | ⚠️ 理论可行但开发量大：需要全屏截图→OCR→正则提取消息→坐标定位输入框→模拟输入。无现成框架 |
| 实时性 | ⚠️ OCR 每轮 1-3 秒，不适合实时监控，只能定时轮询（每 5-10 秒截一次） |
| B站/小红书参考 | 未找到企微 OCR 自动化教程 |

**步骤2结论：**
- 企微 4.x Canvas UI 是硬伤，控件树方案完全不可用
- 纯 OCR 全屏截图方案理论可行但开发量大、实时性差、精度依赖 OCR 模型
- 没有现成开源项目可参考，需要从零搭建
- **不推荐作为 MVP 首选**，可作为长期自研备选

#### 步骤2深入发现

| 调研项 | 结果 |

| 独特价值 | 如果未来企微开放更多 API → MCP 集成层可复用 |

**步骤2结论：**
- MCP Server 是集成层，不是独立的采集方案
- 如果底层基于智能机器人 API → 继承 @限制，不适合接单群场景
- 价值在于"如果找到可用的收消息方案，MCP 层可以快速接入 AI Agent"
- **当前不推荐作为采集方案，但可作为 AI 集成架构的参考**

## 推荐路线

### 短期（MVP 验证）：影刀 RPA 社区版

**理由**：
1. **零代码、当天可测**——不需要写任何代码，拖拽编排即可验证核心问题
2. **有专门企微群消息指令**——不是通用 OCR，是针对企微的封装指令
3. **免费**——社区版个人非商业免费，验证阶段无成本
4. **收发一体**——同时满足采集 + 回复，不需要混合方案
5. **AI 可接入**——影刀支持 Python 脚本节点，可接 LLM 做"大脑"

**验证目标**：
- 企微接单群新消息能否自动捕获？
- 能否根据消息内容自动回复？
- 实时性如何（延迟几秒）？
- 稳定性如何（长时间运行是否出错）？

### 中期（产品化评估）：双轨并行

**轨道 A — 调研会话存档 API（#8）**：
- 如果会话存档 API 费用可接受 + 告知同意流程可行 → 这是"收"端最合规方案
- 发消息端配合 wecom-cli（#9）或智能机器人（#7）
- 优势：官方 API、无封号风险、可产品化
- 需要确认：费用、告知同意流程、5天限制是否影响使用

**轨道 B — 评估 Android 无障碍（#3 WorkTool）**：
- 在模拟器上实测 WorkTool 当前是否仍兼容企微
- 如果兼容 → 二次开发为自主可控的开源方案
- 优势：免费、自主可控、可产品化
- 风险：代码停更、企微 UI 改版需维护

### 长期（产品化）：自研采集引擎

基于 MVP 验证结果 + 中期调研结论，设计 Nigredo 采集引擎架构：
- 收消息：会话存档 API（合规优先）或 Android 无障碍（成本优先）
- 发消息：wecom-cli / 智能机器人（合规）或 影刀 RPA（快速）
- AI 集成：MCP Server 架构参考，实现"手脚+大脑分离"
